# Step-counter implementation notes

Metabasis uses the phone's Android motion sensors directly; it does not read or write Health Connect data and does not require a network connection. The preferred source is `Sensor.TYPE_STEP_COUNTER`, which reports steps since the last device reboot. Android's [step-counter guide](https://developer.android.com/health-and-fitness/fitness/basic-app/read-step-count-data) specifically says the sensor listener should remain registered to collect events and demonstrates a foreground service; Android's [health foreground-service type](https://developer.android.com/develop/background-work/services/fgs/service-types) lists `ACTIVITY_RECOGNITION` as a valid runtime prerequisite. Metabasis persists the last raw sensor value, differences new readings, and treats a lower reading as a device reboot. A persistent health foreground service records day-by-day local totals and attempts restart after boot/package update; Android's evolving background-start rules can still prevent an automatic restart, in which case opening the app resumes collection.

The fallback order is `TYPE_STEP_DETECTOR`, then an explicitly labelled accelerometer threshold detector. A hardware sensor's count is the best input exposed by that phone, not a promise of identical accuracy across models. Sensor-only mode also lacks activity context, so it can inherit false detections from a device's firmware. The accelerometer fallback is approximate and must not be presented as sensor-equivalent.

## Open-source projects reviewed

- [Pedometer by j4velin](https://github.com/j4velin/Pedometer) uses `TYPE_STEP_COUNTER`, a foreground listener, local day accounting and reboot-aware offsets. It declares the hardware feature required, so it does not serve every device. Relevant sources: [SensorListener](https://github.com/j4velin/Pedometer/blob/master/src/main/kotlin/de/j4velin/pedometer/SensorListener.kt), [StepAccounting](https://github.com/j4velin/Pedometer/blob/master/src/main/kotlin/de/j4velin/pedometer/domain/StepAccounting.kt), [manifest](https://github.com/j4velin/Pedometer/blob/master/src/main/AndroidManifest.xml).
- [Stepsy](https://github.com/nvllz/stepsy) uses the hardware counter, with a separate optional vehicle-activity filter in its full build. Its FOSS build stays sensor-only and offline. A maintainer discussion acknowledges the trade-off between filtering vehicle vibration and retaining genuine walking steps. Sources: [MotionService](https://raw.githubusercontent.com/nvllz/stepsy/master/app/src/main/java/com/nvllz/stepsy/service/MotionService.kt), [FOSS/full filter](https://raw.githubusercontent.com/nvllz/stepsy/master/app/src/full/java/com/nvllz/stepsy/service/ActivityRecognitionManager.kt), [issue discussion](https://github.com/nvllz/stepsy/issues/68).
- [Path](https://github.com/sidhant947/Path) uses `TYPE_STEP_COUNTER` in a foreground service and falls back to a threshold-based accelerometer detector. Optional Health Connect export is separate from counting. Sources: [step service](https://raw.githubusercontent.com/sidhant947/Path/main/app/src/main/java/com/sidhant/path/service/StepTrackingService.kt), [step repository](https://raw.githubusercontent.com/sidhant947/Path/main/app/src/main/java/com/sidhant/path/data/StepRepository.kt), [motion classifier](https://raw.githubusercontent.com/sidhant947/Path/main/app/src/main/java/com/sidhant/path/service/MotionDetector.kt).
- [Privacy Friendly Pedometer](https://github.com/SecUSo/privacy-friendly-pedometer) offers hardware counter/detector modes and an accelerometer path, with local hourly/daily storage and foreground/boot behavior. Its help text warns that hardware reliability varies across phones. Sources: [hardware service](https://github.com/SecUSo/privacy-friendly-pedometer/blob/master/app/src/main/java/org/secuso/privacyfriendlyactivitytracker/services/HardwareStepService.java), [sensor service](https://github.com/SecUSo/privacy-friendly-pedometer/blob/master/app/src/main/java/org/secuso/privacyfriendlyactivitytracker/services/AbstractStepDetectorService.java), [help strings](https://github.com/SecUSo/privacy-friendly-pedometer/blob/master/app/src/main/res/values/strings.xml).
- [MotionMate](https://github.com/0xf4b1/motionmate) prefers `TYPE_STEP_COUNTER` and contains a software accelerometer fallback, but the inspected code does not publish validation measurements. Sources: [motion service](https://raw.githubusercontent.com/0xf4b1/motionmate/master/app/src/main/java/com/tiefensuche/motionmate/service/MotionService.kt), [accelerometer detector](https://raw.githubusercontent.com/0xf4b1/motionmate/master/app/src/main/java/com/tiefensuche/motionmate/service/StepDetector.kt), [boot receiver](https://github.com/0xf4b1/motionmate/blob/master/app/src/main/java/com/tiefensuche/motionmate/service/OnBootReceiver.kt).

No reviewed source published a defensible across-device accuracy percentage. Metabasis therefore does not claim a percentage; accuracy must be checked against a manual count on each target handset and walking/carrying condition.
